面试官顺着一个 RPC 项目继续问，问题很快就会落到具体实现上：

  • TCP 只有字节流，粘包、半包怎么处理？
  • 同一条长连接发出多个请求，响应回来后怎么找到对应的调用方？
  • 服务实例上下线以后，客户端怎样及时拿到新地址？
  • 请求超时后，CompletableFuture 和在途请求 Map 怎么清理，复用的 Channel 要不要关闭？
  • 新增一种序列化方式，为什么不应该继续往 switch 里加分支？

只记住“RPC 让远程调用像本地调用一样简单”，遇到这些追问很难往下讲。《手写 RPC 框架》围绕一个可以运行的 Java 项目，把动态代理、网络通信、自定义协议、序列化、注册中心、负载均衡、异步调用和异常处理串在一起。

如果你还不熟悉 RPC 的概念和调用流程，可以先阅读 JavaGuide 的免费文章：RPC 远程过程调用详解。

项目介绍

guide-rpc-framework 是一个面向学习和工程实践的轻量级 RPC 框架。项目保留了早期 Socket 版本，也提供了基于 Netty 的实现，方便对照 BIO 与 NIO 在连接、线程和请求处理方式上的差异。

项目地址（欢迎 Star）：

  • GitHub：https://github.com/Snailclimb/guide-rpc-framework
  • Gitee：https://gitee.com/SnailClimb/guide-rpc-framework

项目代码完全开源。配套教程是 JavaGuide 知识星球内部小册，当前包含 15 篇正文，以及一篇简历写法和面试常见问题解答。

一次 RPC 调用经过了什么

以 @RpcReference 注入的服务接口为例，一次调用会经过这些环节：

本地接口调用
    ↓
JDK 动态代理组装 RpcRequest
    ↓
ZooKeeper 服务发现
    ↓
一致性哈希选择服务实例
    ↓
建立或复用 Netty Channel
    ↓
协议编码、序列化与压缩
    ↓
服务端拆帧、解码并执行目标方法
    ↓
响应按 requestId 完成对应 CompletableFuture

教程不会停在“客户端发送请求、服务端返回结果”这一层。协议字段怎样排列、服务端为什么不能在 I/O 线程里执行耗时方法、请求从排队到收到响应如何共用一个超时预算，这些问题都会结合当前代码说明。

当前项目实现了哪些能力

模块 当前实现
网络通信 Socket 与 Netty 两种传输实现，Netty 支持 Channel 复用和心跳检测
通信协议 16 字节固定头部，包含魔数、版本、完整长度、消息类型、编解码编号和请求编号
消息边界 基于长度字段拆帧，并限制帧及解压后消息体最大为 8 MiB
序列化与压缩 支持 Hessian、Kryo、Protostuff 和 Gzip，默认序列化方式为 Hessian
服务注册发现 使用 ZooKeeper 临时节点和 CuratorCache，支持本地地址缓存与会话恢复
负载均衡 默认使用一致性哈希，每个物理节点对应 160 个虚拟节点
请求响应关联 使用 requestId -> CompletableFuture 管理并发请求，处理超时、取消、断连和关闭清理
调用方式 提供同步代理和返回 CompletableFuture 的异步镜像接口
扩展机制 自定义命名 SPI，覆盖序列化、压缩、负载均衡、注册中心、服务发现和传输层
Spring 集成 使用 @RpcScan、@RpcService、@RpcReference 完成扫描、服务发布与代理注入
错误处理 使用 0～16 的稳定状态码区分参数错误、超时、资源耗尽、服务不可用和内部错误
自动化测试 共 82 项测试，覆盖配置、SPI、编解码、代理、传输、服务处理和 ZooKeeper 会话恢复

这仍然是一个教学和工程实践项目。自动重试、熔断、限流、TLS、调用方鉴权、远程取消、监控中心以及服务端有界任务队列尚未实现。教程会直接标出这些限制，避免把成熟 RPC 框架的能力套到当前代码上。

这套教程怎么讲

教程先用 Socket 和 JDK 动态代理搭出最小调用链，再逐步换成 Netty、自定义协议、可插拔序列化和 ZooKeeper。读者可以看到每次改造解决了哪个问题，而非直接面对一套已经组装好的代码。

源码分析部分按真实调用顺序展开。客户端怎样生成请求、服务发现怎样选择地址、编解码器怎样处理消息、服务端怎样执行方法、响应怎样完成 Future，都能在文章和代码之间对应起来。

后面的 SPI、负载均衡和测试章节继续处理扩展与失败场景。除了正常调用，也会讨论重复 requestId、响应晚到、请求超时、连接提前关闭、非法协议帧和 ZooKeeper 会话失效。

运行项目所需的环境、启动顺序和第一次 RPC 调用继续放在项目 README 的“快速开始”中维护，不再单独拆一篇重复文章。

适合谁学习

  • 已经学过 Java 基础、集合、反射和多线程，想把这些知识放进一个完整项目中使用。
  • 接触过 Netty 或 ZooKeeper，但对它们在 RPC 调用链里的职责还比较模糊。
  • 正在准备 Java 后端校招、社招，希望增加一个能深入讲协议、网络和分布式协作的项目。
  • 平时会使用 Dubbo、Feign 等远程调用工具，想继续理解代理、协议、注册发现和响应关联是怎样实现的。
  • 准备阅读 Dubbo、Netty 等框架源码，希望先用一个体量较小的项目建立整体认识。

第一次接触 RPC 没关系，但最好已经掌握 Java 基础语法、Maven 和基本的客户端/服务端概念。教程不会花大量篇幅重复这些前置知识。

建议学习顺序

  1. 按项目 README 准备 JDK 25、Maven 3.9 和 ZooKeeper 3.9.5，先跑通服务端与客户端。
  2. 阅读前 8 篇教程，自己完成 Socket、代理、Netty 和 ZooKeeper 的最小实现。
  3. 对照第 9～14 篇阅读当前源码，至少亲手改造一个扩展点，例如新增序列化器或负载均衡策略。
  4. 执行 mvn verify，再补一个超时、断连或非法帧测试，确认自己能解释失败后的资源清理。
  5. 最后整理简历并准备追问。没有亲手验证过的能力，不写进项目经历。
